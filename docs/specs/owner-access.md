# Доступ владельца

Правила для [задачи №7](https://github.com/atankeev/ai-for-developers-project-386/issues/7).

[Согласованный итог обсуждения](https://github.com/atankeev/ai-for-developers-project-386/issues/7#issuecomment-6750603535).

Схема доступа, требования к конфигурации и проверяемые сценарии подтверждены пользователем. Реализация выполняется отдельным этапом.

## Согласованные условия

Владелец единственный и заранее задан; вход по логину и паролю, без регистрации. В гостевом интерфейсе нет ссылки на кабинет; знание его адреса не даёт доступа.

Публикация учебного проекта необязательна. Локально используется HTTP. Если приложение публикуется, принимаются один экземпляр приложения, сайт и `/api` на одном домене и HTTPS, обеспечиваемый хостингом.

Логин и хеш пароля задаются конфигурацией сервера. Смена и восстановление доступа выполняются обновлением конфигурации с перезапуском приложения. Формы смены пароля и восстановления по email не нужны. Секреты и действующие учётные данные не включаются в репозиторий или спецификацию.

Сессия действует 12 часов с момента входа без продления по активности. Допустимы одновременные сессии на нескольких устройствах. Выход завершает текущую сессию. Таймера бездействия и опции «Запомнить меня» нет.

## Сессии

Используются `@fastify/session` и `@fastify/cookie`. Сессии хранятся в памяти единственного экземпляра сервера; отдельное хранилище не требуется. Cookie содержит случайный идентификатор сессии, а не логин, пароль или данные гостей. Перезапуск завершает все сессии, в том числе при смене учётных данных.

Cookie имеет `HttpOnly`, `SameSite=Strict` и, при публикации по HTTPS, `Secure`. Для локального HTTP `Secure` отключён. Выход уничтожает текущую серверную сессию и удаляет cookie; другие устройства остаются авторизованными.

## Защита запросов

Вход ограничен пятью попытками в минуту с одного IP. Ошибка неверного логина и пароля одинакова. CAPTCHA и блокировки учётной записи нет. Для изменяющих запросов, включая вход и выход, проверяется `Origin`; cookie имеет `SameSite=Strict`.

## Потеря доступа

Если сессия отсутствует или истекла, интерфейс переходит на страницу входа с сообщением «Сессия завершена, войдите снова». Несохранённые изменения теряются. После входа открывается нужный раздел с актуальными данными; запросы изменения автоматически не повторяются.

Потеря ответа не означает, что операция не выполнена. Если результат предыдущего запроса неизвестен, после восстановления доступа сначала загружаются актуальные данные с сервера.

## Конфигурация и границы защиты

- Все API управления типами встреч, расписанием и записями, а также чтения полных данных гостей проверяют серверную сессию до выполнения операции. Защита только в интерфейсе недостаточна. Публичные каталог, доступность, создание записи и подтверждение по секретной ссылке остаются без входа владельца. Отсутствующая, недействительная или истёкшая сессия даёт `401`, без изменения данных.
- Cookie действует до конца 12-часового срока и сохраняется при закрытии браузера. Проверка срока выполняется сервером; активность срок не продлевает. Успешный вход создаёт новый идентификатор сессии. Недействительная cookie не восстанавливает уничтоженную сессию.
- В конфигурации обязательны логин, хеш пароля, секрет подписи cookie и разрешённый origin сайта. При отсутствии или некорректности обязательной конфигурации сервер не запускается; стандартных логина и пароля нет. Секрет подписи не совпадает с паролем. Хеш создаётся отдельной локальной командой с интерактивным скрытым вводом пароля; предлагается встроенный Node.js `scrypt` со случайной солью и сохранёнными параметрами. Пароль не передаётся аргументом командной строки и не записывается в файл конфигурации открытым текстом.
- Origin сравнивается точно с настроенным адресом сайта, включая схему и порт. Изменяющие запросы с отсутствующим, `null` или чужим Origin отклоняются (`403`); исключений для входа нет. GET-запросы не изменяют данные; вход и выход выполняются POST-запросами. Cross-origin-доступ с credentials не разрешается.
- Лимит входа учитывает все попытки, действует в памяти сервера и сбрасывается при перезапуске. Превышение возвращает `429` и `Retry-After`. Чужие IP не блокируются вслед за одним клиентом. За reverse proxy доверяются только явно настроенные прокси; произвольному `X-Forwarded-For` доверять нельзя. В публикации IP клиента должен определяться корректно, чтобы все посетители не делили лимит прокси.
- Ответы входа и приватного API имеют `Cache-Control: no-store`. Пароль, хеш, секреты, Cookie/Set-Cookie, токены гостевых ссылок и имя/email/комментарий гостя не попадают в логи. Это относится и к телам запросов, заголовкам и URL; при использовании секретов в URL их нужно скрывать.

## Проверяемые сценарии

1. Без конфигурации учётных данных и обязательных параметров сервер не запускается; стандартного доступа нет.
2. Правильный логин и пароль открывают кабинет; неверный логин и неверный пароль дают одинаковую ошибку без создания сессии.
3. После успешного входа идентификатор сессии новый; cookie не содержит учётных данных или данных гостей.
4. Прямые запросы к каждому API управления и чтения данных гостей без действующей сессии возвращают `401`, не раскрывают данные и не выполняют изменение.
5. Гостевые каталог, доступность, создание записи и секретное подтверждение доступны без сессии владельца в пределах уже согласованных правил. Подтверждение не раскрывает данные гостя.
6. Сессия действительна до истечения 12 часов от входа, в момент истечения недействительна; активность срок не продлевает. Закрытие браузера до этого срока не завершает вход.
7. Вход на двух устройствах работает одновременно; выход на одном не завершает сессию другого. Повторное использование cookie вышедшей сессии не даёт доступа.
8. Перезапуск сервера завершает все сессии. После смены конфигурации и перезапуска старый пароль не подходит, новый подходит.
9. Шестая попытка входа с одного IP за минуту получает `429` с `Retry-After`; другой IP продолжает работать. После окончания окна попытки снова разрешены. Поддельный `X-Forwarded-For` от недоверенного клиента не обходит лимит.
10. Изменяющий запрос с чужим, отсутствующим или `null` Origin отклоняется без изменения данных, включая вход и выход. Запрос с разрешённым Origin работает при выполнении остальных проверок.
11. В локальном HTTP вход работает без Secure-cookie; при публикации cookie имеет Secure и передаётся только по HTTPS. В обоих режимах заданы HttpOnly и SameSite=Strict.
12. Сессия истекла во время редактирования: переход на вход с сообщением, несохранённая форма теряется; после входа открывается нужный раздел и загружаются актуальные данные. Изменение автоматически не повторяется.
13. Ответ на изменение потерялся: интерфейс не сообщает об успехе без подтверждения и не повторяет изменение автоматически; после восстановления доступа загружает актуальное состояние.
14. Приватные ответы не кэшируются; секреты и персональные данные отсутствуют в логах, в том числе при неуспешном входе и ошибках запросов.

## Границы

Постоянное хранение предметных данных выбирается в задаче №9 и не требуется для сессий выбранной схемы. Подробные состояния экранов относятся к №8; правила потери доступа выше обязательны для них. Защита гостевого бронирования от спама не определяется ограничением попыток входа владельца.

Новых предметных терминов для GLOSSARY.md не возникло. Отдельный ADR не требуется: выбранная схема рассчитана на один экземпляр учебного приложения, легко заменяется и не привязывает предметные данные к хранилищу сессий. Обоснование выбора сессий в памяти — отсутствие необходимости в отдельном хранилище при допустимом завершении всех входов после перезапуска.
